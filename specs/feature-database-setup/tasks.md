# Tasks: Database Migration to PostgreSQL

**Input**: Design documents from `specs/feature-database-setup/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/, quickstart.md

**Tests**: Included. FR-013 requires the suite to run on PostgreSQL, and constitution principle IV
requires tests for every behaviour change. Within each story, write the tests first and confirm
they fail before implementing.

**Organization**: Tasks are grouped by user story so each story can be implemented and tested on
its own. The PostgreSQL connection and schema are shared by every story, so they sit in Phase 2.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies on incomplete tasks)
- **[Story]**: User story from spec.md (US1–US4)
- Paths are relative to the repository root (single Flask package, see plan.md)

## Implementation Strategy

### MVP (User Stories 1 + 2, both P1)

1. Phase 1 Setup, Phase 2 Foundational
2. US1: data move and verification
3. US2: app fully on PostgreSQL
4. **Stop and validate**: full `pytest`, quickstart §3 and §4. This is the smallest release that is useful: US1 alone moves data the app cannot read yet, and US2 alone gives an empty database.

### Incremental Delivery

1. MVP (US1 + US2)
2. US3: multi-server confidence
3. US4: maintenance mode and rehearsed runbook; required before the real production cutover
4. Polish: docs, constitution amendment, performance check
